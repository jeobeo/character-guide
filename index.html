The short version

Nothing gets re-modelled or re-rigged. The full body comes from the stylized base male, the clothes come from the clothed Scrappy, and every piece follows the one skeleton the game already animates.

One skeleton, never changed

The 62-bone armature Skeleton inside CM_Scrappy.fbx. Every body and item is skinned to it in the same rest pose. Nobody renames, re-rolls or re-poses it.

One piece, one FBX

Bodies, clothes and backpacks are skinned to the skeleton. Masks and hats are plain meshes that sit on a head socket, so they're quick to make in large numbers.

Hide skin, don't delete it

The body stays whole. Each item says which body regions it covers, and the game hides those. It's what Alex did by hand on the clothed version, done per outfit.

In Unity today

  • ScrappyCharacter.prefab (Assets/Resources/Prefabs/Characters/) is the live character. BGMCharacter is its gameplay script. The BGMCharacter.fbx model is an old robot rig that only a backup prefab uses.
  • The prefab points at CM_Scrappy's bones 92 times (FinalIK, Legs Animator, the hand, chest and foot sockets). That's why the skeleton can never change.
  • Animation is Animancer playing Humanoid clips through CM_Scrappy's avatar. Any body on the same skeleton gets every animation for free.
  • Bone names are Unity-style (Hips, Spine, Left_UpperArm…). The CC_Base files next to the FBX (.ini, .json, .iAvatar, back/) are old AccuRIG leftovers.
  • The player's name already replicates through Player. The outfit copies that pattern so it survives death and respawn.
  • No customisation exists yet.

What we're building

Same prefab, same gameplay. The only change is that the visible pieces become separate meshes under Mesh, all following the skeleton inside CM_Scrappy.

Grey already exists · teal new code (Joe) · rust meshes from Alex

Male ↔ female

Both bodies share the skeleton and the avatar, so animations, IK and hit reactions just work. Switching body swaps the Body piece, then each item switches to its female fit, stays on if it fits anyone, or falls back to that slot's default until you switch back.

Hiding skin

The body is split into 12 regions (Chest, Thighs, Feet…). A shirt says "I cover Chest, Stomach, UpperArms" and the body hides those while it's worn. The same regions exist on every body, so one item works on all of them.

Team masks

Every player on a team wears the team's mask. Each team entry in the gamemode names its mask, and every machine already knows each character's team, so masks need no networking of their own.

Skin tone

One body texture, tinted in the shader from a palette of tones. The player's tone is one number in their saved outfit. Eyes, teeth and lips are masked out so they keep their colour.

Why this approach

Checked against how we work: lots of masks, swappable clothes and bodies, skin tones, 16 players, laptops on the Performant setting, and a character whose IK and animation already work.

OptionVerdictWhy
Skinned pieces on one shared skeletonUse for bodies, clothes, backpacksKeeps Animancer, FinalIK, Legs Animator and all 92 bone references untouched. Alex keeps modelling and weighting normally in Blender. It's the standard way multiplayer games do outfits.
Plain meshes on a head socketUse for masks and hatsNo weights, no skeleton in the file, cheapest to draw. A new mask takes minutes to add, and the same prefab can be shown on a team-select screen or a banner.
Character-creator frameworks (UMA and similar)NoThey take over the rig, materials and prefab, and would fight the Animancer and IK setup that already works.
One pre-made mesh per outfitNoEvery mask times every outfit times every body multiplies into hundreds of files.
Deleting skin under clothes per outfitNoOnly works for one outfit. Region hiding does the same job for any combination.
Merging each character's pieces into one mesh at runtimeLater, if neededSaves draw calls with many players. Mesh Baker is already in the project if the profiler asks for it.

Masks & teams

Masks are the main thing players customise and how teams recognise each other, so they get the simplest pipeline: a plain mesh, modelled on the head, dropped onto a socket.

Alex

Making a mask

  1. In the master file, model it on Body_M_01's head in rest pose and put it in the Mask collection.
  2. No Armature modifier, no weights. Leave it exactly where it sits on the head and apply scale.
  3. Check it also fits Body_F_01 once that exists: the whole team shares one mask.
  4. Up to 1.5k triangles and one 1024 texture (512 for simple ones). Several masks can share one texture sheet if that's quicker to paint.
  5. Optional team colour: in the BaseMap alpha, paint white where the team colour should show.
  6. Run the export. It becomes SM_Mask_<Name>.fbx.
Joe

Socket and team setup

  1. Once: in ScrappyCharacter, create an empty as a child of CM_Scrappy with zero position and rotation, then drag it onto the Head bone (Unity keeps its world position). Name it Socket_Head. It now carries the model's origin with the head, so a mask exported in place lands exactly where Alex modelled it.
  2. Each mask: a WardrobeItem (slot Mask, hides Face, plus Head for full helmets) pointing at the SM_ prefab. Equipping means instantiating it under Socket_Head at zero.
  3. Teams: add Mask and Colour to TeamDefinition in BasicGamemode.cs. At start the gamemode registers them in a small TeamMasks lookup in the character assembly (the character code can't see the gamemode). BGMCharacter.OnTeamChanged, empty today, re-applies the outfit.
  4. The character wears its team's mask while it has one, otherwise the player's own pick. Team is already a SyncVar, so there's nothing new to send.
  5. If teams later choose masks in a lobby, move the choice into a synced list on the gamemode. Nothing else changes.

[Serializable]
public class TeamDefinition
{
    public string TeamName;
    public SpawnGroup SpawnGroup;
    public WardrobeItem Mask;           // everyone on this team wears it
    public Color Colour = Color.white;  // tints the mask's team-colour areas
}
// In the gamemode's start-up on every peer:
//     TeamMasks.Register(Teams.Select(t => (t.Mask, t.Colour)).ToArray());

// TeamMasks.cs (Scrapsized.Characters, next to WardrobeItem)
/// <summary>Team id -> mask. Filled by the gamemode, read by the character, which can't see the gamemode.</summary>
public static class TeamMasks
{
    static (WardrobeItem Mask, Color Colour)[] s_Teams = System.Array.Empty<(WardrobeItem, Color)>();

    public static void Register((WardrobeItem Mask, Color Colour)[] teams) => s_Teams = teams;

    public static bool TryGet(int team, out WardrobeItem mask, out Color colour)
    {
        bool known = team >= 0 && team < s_Teams.Length && s_Teams[team].Mask != null;
        mask = known ? s_Teams[team].Mask : null;
        colour = known ? s_Teams[team].Colour : Color.white;
        return known;
    }
}

1 · Set up the master file

  1. Start from the .blend that exported CM_Scrappy.fbx (mesh Clothing.002, armature Skeleton). If that's gone, import the FBX with Automatic Bone Orientation off.
  2. File › Import › FBX BodyBaseMesh_01.fbx with default settings. It lands at the same scale and facing as the clothed version: the heads line up exactly.
  3. Make collections: Bodies, Torso, Legs, Feet, Hands, Mask, Headwear, Backpack, Accessories, and _Reference holding an untouched copy of Clothing.002.
  4. Leave Skeleton alone from here on: same names, same parents, same rest pose, object at the origin with scale 1.
Alex

2 · Put the base body in the T-pose, then weight it

Measured from the two files: the head, torso and legs of both versions already line up (the clothes sit 2–4 cm off the body). Only the arms differ. The base body is in an A-pose, but the skeleton and the clothed version are in a T-pose. The body has to match the skeleton, never the other way round.

  1. Rename the base body Body_M_01 and move it to Bodies.
  2. Bring the clothes down to the body: select Skeleton, Pose Mode, and rotate the shoulder, arm, hand and finger bones until the clothed version's hands and sleeves sit on the base body's arms. The clothed hands are the base body's hands, so they should fit exactly. This is a temporary pose. Don't apply it.
  3. On Body_M_01 add a Surface Deform modifier, target = the _Reference clothed mesh, and press Bind.
  4. On Skeleton: Pose › Clear Transform › All. The clothes go back to the T-pose and carry the body's arms with them. Apply the Surface Deform on Body_M_01.
  5. Copy the weights: add a Data Transfer modifier to Body_M_01, source = the _Reference clothed mesh, tick Vertex Data › Vertex Groups, mapping Nearest Face Interpolated, press Generate Data Layers, apply. Covered areas take the weights of the clothes on top of them; exposed skin gets exactly its old weights.
  6. Add an Armature modifier pointing at Skeleton. Weights › Limit Total (4), Normalize All. Pose-test (arms up, knees bent, spine twist) and fix shoulders, armpits, elbows, hips and knees.

Check: with the skeleton in rest pose, the clothed version's face and hands sit exactly on Body_M_01 again.

Materials: the base body has three (Body A, Body B, Set_C). Keep them. The clothed version only ever used Body A, so check that Body B's texture is finished in the areas the clothes used to hide. Size: 26k triangles. That's fine to start with; if laptops struggle later, a 15k version is the first saving.

3 · Cut the items out of the clothed version

  1. Duplicate Clothing.002. On the copy: Edit Mode, P › By Material. Weights, UVs and materials all survive.
  2. Delete the Body_A piece. Body_M_01 replaces it.
  3. Split each set into items: hover a part, L to select it, P › Selection. Name it using the naming pattern and drop it in its slot collection.
  4. Items cut from the same set keep that set's material. Nothing needs re-texturing to start.
  5. Weights › Limit Total (4), Normalize All on each item.
  6. Masks and hats (like the skull mask in Set C): delete their Armature modifier and vertex groups and move them to Mask or Headwear. They export as plain meshes, in place. See Masks & teams.

6 · Textures

  • Skin tone: paint the body's skin in a light, fairly neutral tone (the game can darken it, not lighten it), and put a tint mask in the BaseMap alpha on every body texture: white where skin tone applies, black for eyes, teeth and anything else that keeps its colour.
  • Substance Painter export preset Unity Universal Render Pipeline (Metallic Standard).
  • One UV set per item, its own 0–1 space.
  • Sizes: body, torso, legs 2048; feet, hands, mask, hats 1024; small bits 512. Laptops on the Performant setting show textures at half size anyway.
  • Triangle budgets: torso 5k, legs 4k, backpack 4k (today's is about 7k), feet 2k, hat 2k, mask 1.5k.
Alex

7 · Export everything with one command

The script exports every mesh in the slot collections straight into the Unity project with identical settings every time: skinned pieces as SK_<name>.fbx (with the skeleton), masks and hats as SM_<name>.fbx (mesh only, in place). Anything named with a leading _ is skipped. Run it from the repository root:

"C:\Program Files\Blender Foundation\Blender 4.5\blender.exe" -b ArtSource/Characters/Scrappy/Scrappy_Master.blend --python ArtSource/Tools/export_scrappy_parts.py -- .

Change the Blender path to your version. Joe presses Ctrl R in Unity to pick the files up.

export_scrappy_parts.py (save in ArtSource/Tools/) 
"""Exports every body and wardrobe piece in Scrappy_Master.blend as its own FBX.

blender -b Scrappy_Master.blend --python export_scrappy_parts.py -- <unity project folder>
"""
import os
import sys
import bpy

ARMATURE = "Skeleton"                        # the master armature. Never rename.
OUT = "Assets/Art/Characters/Scrappy"
FOLDERS = {                                  # Blender collection -> Unity folder
    "Bodies": "Bodies",
    "Torso": "Wardrobe/Torso", "Legs": "Wardrobe/Legs", "Feet": "Wardrobe/Feet",
    "Hands": "Wardrobe/Hands", "Mask": "Wardrobe/Mask", "Headwear": "Wardrobe/Headwear",
    "Backpack": "Wardrobe/Backpack", "Accessories": "Wardrobe/Accessories",
}
SOCKET = {"Mask", "Headwear"}                # plain meshes on Socket_Head, exported in place
REGIONS = ["Head", "Face", "Neck", "Chest", "Stomach", "UpperArms",
           "Forearms", "Hands", "Hips", "Thighs", "Shins", "Feet"]

project = os.path.abspath(sys.argv[sys.argv.index("--") + 1])
armature = bpy.data.objects[ARMATURE]


def bake_regions(obj):
    """Bodies: Region_* vertex groups -> second UV map 'Regions' (u = region index, one value per face)."""
    index_of = {g.index: REGIONS.index(g.name[7:]) for g in obj.vertex_groups
                if g.name.startswith("Region_") and g.name[7:] in REGIONS}
    if not index_of:
        return
    mesh = obj.data
    uv = mesh.uv_layers.get("Regions") or mesh.uv_layers.new(name="Regions")
    region_of = {}
    for v in mesh.vertices:
        for g in v.groups:
            if g.group in index_of and g.weight > 0.5:
                region_of[v.index] = index_of[g.group]
    for poly in mesh.polygons:
        votes = {}
        for vi in poly.vertices:
            if vi in region_of:
                votes[region_of[vi]] = votes.get(region_of[vi], 0) + 1
        region = max(votes, key=votes.get) if votes else 0
        for li in poly.loop_indices:
            uv.data[li].uv = (region + 0.5, 0.0)


def export(objects, path):
    bpy.ops.object.select_all(action="DESELECT")
    for o in objects:
        o.hide_set(False)
        o.select_set(True)
    bpy.context.view_layer.objects.active = objects[0]
    os.makedirs(os.path.dirname(path), exist_ok=True)
    bpy.ops.export_scene.fbx(
        filepath=path, use_selection=True, object_types={"ARMATURE", "MESH"},
        apply_unit_scale=True, apply_scale_options="FBX_SCALE_UNITS",
        axis_forward="-Z", axis_up="Y",
        use_mesh_modifiers=True, mesh_smooth_type="FACE",
        add_leaf_bones=False, use_armature_deform_only=True,
        primary_bone_axis="Y", secondary_bone_axis="X",
        bake_anim=False, path_mode="STRIP", embed_textures=False)
    print("Exported", path)


for collection, folder in FOLDERS.items():
    coll = bpy.data.collections.get(collection)
    if coll is None:
        continue
    for obj in coll.all_objects:
        if obj.type != "MESH" or obj.name.startswith("_"):
            continue
        skinned = any(m.type == "ARMATURE" for m in obj.modifiers)
        if collection in SOCKET:
            if skinned:
                print("SKIPPED (masks and hats must not be skinned):", obj.name)
                continue
            export([obj], os.path.join(project, OUT, folder, "SM_" + obj.name + ".fbx"))
            continue
        if not skinned:
            print("SKIPPED (not skinned to Skeleton):", obj.name)
            continue
        if collection == "Bodies":
            bake_regions(obj)
        export([obj, armature], os.path.join(project, OUT, folder, "SK_" + obj.name + ".fbx"))

1 · Import rules

Files landing in Assets/Art/Characters/Scrappy/ get the right settings automatically on first import. SK_ pieces: Humanoid with the avatar copied from CM_Scrappy (which also flags a renamed bone). SM_ masks and hats: plain meshes. No materials, no lightmap UVs.

ScrappyCharacterImportRules.cs (editor assembly) 
using System.IO;
using System.Linq;
using UnityEditor;
using UnityEngine;

namespace Scrapsized.Editor
{
    /// <summary>
    /// First-import settings for Scrappy bodies, wardrobe pieces and animations, chosen by folder so nobody has
    /// to remember them. Pieces copy the master avatar from CM_Scrappy, which fails loudly on a renamed bone.
    /// </summary>
    sealed class ScrappyCharacterImportRules : AssetPostprocessor
    {
        const string Root = "Assets/Art/Characters/Scrappy/";
        const string MasterRig = "Assets/Meshes/CM_Prefab_01/CM_Scrappy.fbx";

        void OnPreprocessModel()
        {
            if (!assetPath.StartsWith(Root)) return;
            var importer = (ModelImporter)assetImporter;
            if (!importer.importSettingsMissing) return; // only the first import; later tweaks stand

            string file = Path.GetFileName(assetPath);
            bool animation = assetPath.StartsWith(Root + "Animations/");
            bool ownRig = !animation || file.StartsWith("A_Scrappy_");

            importer.importAnimation = animation;
            importer.materialImportMode = ModelImporterMaterialImportMode.None; // materials live on the item asset
            importer.generateSecondaryUV = false;                               // UV1 carries body regions
            importer.isReadable = false;

            if (file.StartsWith("SM_"))
            {
                importer.animationType = ModelImporterAnimationType.None;       // masks and hats: plain meshes
                return;
            }

            importer.animationType = ModelImporterAnimationType.Human;
            importer.optimizeGameObjects = false;
            importer.skinWeights = ModelImporterSkinWeights.Standard;           // 4 bones per vertex

            if (ownRig)
            {
                importer.avatarSetup = ModelImporterAvatarSetup.CopyFromOther;
                importer.sourceAvatar = AssetDatabase.LoadAllAssetsAtPath(MasterRig).OfType<Avatar>().FirstOrDefault();
            }
            else
            {
                importer.avatarSetup = ModelImporterAvatarSetup.CreateFromThisModel; // other rigs retarget via Humanoid
            }
        }
    }
}

3 · Item and body assets

  • BodyDefinition: id, name, fit tag (M, F), body prefab.

        public Material[] Materials;
    }

    /// <summary>The exact fit for this body, else the unisex one, else null (not wearable on it).</summary>
    public Variant VariantFor(BodyDefinition body)
    {
        foreach (var v in Variants) if (v.FitTag == body.FitTag) return v;
        foreach (var v in Variants) if (v.FitTag == "U") return v;
        return null;
    }
}

4 · Putting an item on

Masks and hats (SM_): instantiate under Socket_Head at zero position and rotation, assign materials, update hidden regions. Done.

Everything else (SK_):

  1. Pick the item's prefab for the current body (VariantFor).
  2. Instantiate it under Mesh, so the swim tilt applies to it.
  3. Rebind: point each SkinnedMeshRenderer's bones at the character's own bones with the same names. Bones the character doesn't have (backpack swing bones) move under the character's matching parent bone.
  4. Delete the piece's own copy of Skeleton, set its layer to Character, assign its materials.
  5. Remove whatever was in that slot (and any swing bones it brought).
  6. Update the body's hidden regions: everything worn, combined.
SkeletonBinder.cs (the rebind step) 
using System.Collections.Generic;
using UnityEngine;

/// <summary>
/// Moves a wardrobe piece onto the character's master skeleton by bone name. Item bones (backpack flap, straps)
/// are re-homed under the master bone that matches their original parent, keeping their local rest offset.
/// </summary>
public static class SkeletonBinder
{
    public static Dictionary<string, Transform> Index(Transform skeletonRoot)
    {
        var bones = new Dictionary<string, Transform>();
        foreach (var t in skeletonRoot.GetComponentsInChildren<Transform>(true)) bones[t.name] = t;
        return bones;
    }

    public static void Bind(SkinnedMeshRenderer piece, Dictionary<string, Transform> master)
    {
        Transform[] bones = piece.bones;
        for (int i = 0; i < bones.Length; i++)
        {
            Transform own = bones[i];
            if (own == null) continue;
            if (master.TryGetValue(own.name, out Transform shared)) { bones[i] = shared; continue; }

            // Item bone. Only the top of each chain moves; its children come with it.
            if (own.parent != null && master.TryGetValue(own.parent.name, out Transform newParent))
                own.SetParent(newParent, false);
        }
        piece.bones = bones;
        if (piece.rootBone != null && master.TryGetValue(piece.rootBone.name, out Transform root))
            piece.rootBone = root;
    }
}

5 · Switching body

  1. Swap the Body piece, exactly like an item.
  2. For each worn item: same prefab for the new body → leave it; a different fit → swap it; no fit → wear that slot's default, but remember the choice so switching back restores it.
  3. Apply the hidden regions to the new body.

No avatar change, no Animator.Rebind(), no IK reset: the skeleton is the same objects before and after.

6 · Body shader: hidden skin and skin tone

The export script stores each body face's region number in UV1. One Lit Shader Graph does both jobs: it collapses faces in hidden regions, and tints skin by the tone the player picked. Collapsing in the vertex stage keeps the body fully opaque, so there's no alpha clipping cost, which matters on laptops.

  1. Create › Shader Graph › URP › Lit, named SG_ScrappyBody. Opaque, no alpha clipping. Add BaseMap, Normal and MaskMap like URP Lit.
  2. Skin tone: add a Color _SkinTone (default white). Base Color = Lerp(BaseMap.rgb, BaseMap.rgb × _SkinTone, BaseMap.a). The alpha is Alex's tint mask.
  3. Hidden skin (vertex stage): add a Float _HiddenRegions. UV node (UV1) › Split R › Floor = region. Power(2, region) › Divide(_HiddenRegions by it) › Floor › Modulo 2 = hidden (1 or 0). Vertex Position = Position (Object) × (1 − hidden). Hidden faces shrink to a point and are never drawn, including in shadows.
  4. Skin tones live in a SkinTonePalette asset (a list of colours); the outfit stores the index. The first entry is white, which shows the texture as painted.
  5. The body has three materials; set both values on each. renderer.materials makes per-character copies, so destroy them when the character goes.
  6. Masks can use the same tint trick for team colours: a copy of the graph, SG_ScrappyMask, fed with the team's colour.

Backpack motion

The backpack is a normal item: on, off and swapped like clothing, and its swing bones come and go with it. Motion is added on top of the animation, never instead of it.

Joe

Spring component

  • One SpringChain on the backpack, listing its swing bones parents first. Start with Backpack_Main stiffness 0.35, damping 0.3, and Backpack_Flap 0.08, 0.15.
  • Body colliders are simple spheres (SpringCollider, not physics colliders) on Spine, UpperChest, Hips and Head, set up once on the prefab and given to every item.
  • It stops beyond 30 m from the camera and is off on dedicated servers. The weather can push it through SpringChain.Wind.
  • Later, the same component handles jacket hems, scarves and straps. For real cloth like capes, look at Magica Cloth 2 then. Avoid Unity Cloth on characters.
SpringChain.cs, SpringCollider.cs 
using UnityEngine;

/// <summary>
/// Verlet secondary motion for an item's spring bones (Backpack_Main, Backpack_Flap, strap links). One component
/// per item; bones are listed parents before children. Each bone starts from its rest pose under its already-solved
/// parent every frame, so animation stays in charge and this only adds lag, sway and bounce.
/// </summary>
[DefaultExecutionOrder(20000)] // after Animancer, FinalIK and socket followers (10000)
public sealed class SpringChain : MonoBehaviour
{
    [System.Serializable]
    public struct Bone
    {
        public Transform Transform;
        [Range(0f, 1f)] public float Stiffness;      // pull back towards the animated pose
        [Range(0f, 1f)] public float Damping;
    }

    public Bone[] Bones;                             // parents before children; _Tip bones are not listed
    public Vector3 Gravity = new Vector3(0f, -1.5f, 0f);
    public float Radius = 0.04f;
    public float MaxDistance = 30f;
    public SpringCollider[] Colliders;               // body proxies, set on equip
    public static Vector3 Wind;                      // set by the weather system

    Quaternion[] _rest;
    Vector3[] _localTip, _tip, _previous;

    void OnEnable()
    {
        int n = Bones.Length;
        _rest = new Quaternion[n]; _localTip = new Vector3[n]; _tip = new Vector3[n]; _previous = new Vector3[n];
        for (int i = 0; i < n; i++)
        {
            Transform bone = Bones[i].Transform;
            _rest[i] = bone.localRotation;
            _localTip[i] = TipOf(bone);
            _tip[i] = _previous[i] = bone.TransformPoint(_localTip[i]);
        }
    }

    // The bone's "_Tip" child gives the lever; otherwise its first child.
    static Vector3 TipOf(Transform bone)
    {
        foreach (Transform child in bone) if (child.name.EndsWith("_Tip")) return child.localPosition;
        return bone.childCount > 0 ? bone.GetChild(0).localPosition : Vector3.up * 0.1f;
    }

    void LateUpdate()
    {
        Camera view = Camera.main;
        bool near = view == null || (view.transform.position - transform.position).sqrMagnitude < MaxDistance * MaxDistance;
        float dt = Mathf.Min(Time.deltaTime, 1f / 30f);
        for (int i = 0; i < Bones.Length; i++)
        {
            Transform bone = Bones[i].Transform;
            bone.localRotation = _rest[i];                   // rest pose under the parent solved this frame
            Vector3 target = bone.TransformPoint(_localTip[i]);
            if (!near) { _tip[i] = _previous[i] = target; continue; }

            Vector3 next = _tip[i] + (_tip[i] - _previous[i]) * (1f - Bones[i].Damping) + (Gravity + Wind) * (dt * dt);
            next += (target - next) * Bones[i].Stiffness;
            foreach (SpringCollider c in Colliders) if (c != null) next = c.PushOut(next, Radius);
            float length = (target - bone.position).magnitude;
            next = bone.position + (next - bone.position).normalized * length;

            _previous[i] = _tip[i];
            _tip[i] = next;
            bone.rotation = Quaternion.FromToRotation(target - bone.position, next - bone.position) * bone.rotation;
        }
    }
}

/// <summary>A body proxy for springs. Not a physics collider: the character controller and raycasts never see it.</summary>
public sealed class SpringCollider : MonoBehaviour
{
    public float Radius = 0.12f;

    public Vector3 PushOut(Vector3 point, float extra)
    {
        Vector3 offset = point - transform.position;
        float r = Radius + extra;
        return offset.sqrMagnitude < r * r ? transform.position + offset.normalized * r : point;
    }
}
